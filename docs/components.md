# Components And Modules

## Frontend Shell

`frontend/src/App.tsx` composes the main UI, owns client-only pane width persistence, and hosts the shared source editor dialog used by top-bar quick add, source sidebar actions, and settings source editing:

```text
TopBar
SettingsWorkspace    when view === settings
Sidebar
FeedListPane
DetailPane
SourceEditorDialog
```

State orchestration lives behind the stable `frontend/src/hooks/use-info-flow-app.ts` export. The default AI-home first screen loads sources plus the homepage bootstrap read model, Insight Channels, full-result homepage summary/facets, the first item window, the short-lived homepage snapshot token when one is returned, and active backend operations, then fetches reader detail for the auto-selected AI/Reader item so the right pane can render full detail data. Reader items are loaded on the first Reader view switch, and Knowledge saved items are loaded on Knowledge view/search. List loading state is tracked per view (`ai`, `reader`, and `kb`) so a failed refresh can show retry UI without discarding the previous ready list. Local hook modules under `frontend/src/hooks/info-flow/` own helper utilities plus homepage read-model, operation tracking, and source-editor controller slices; `use-info-flow-app.ts` remains the app-level orchestrator and `useInfoFlowApp()` entrypoint for `App.tsx`.

Resizable sidebar/list widths are stored in localStorage key `ifa:layout:pane-widths:v1`. This is presentation state only and is not a backend setting.

## RSS Short Content Extraction Notes

- `detail-pane.tsx` shows a compact capture summary card for reader/homepage details under the title and above the AI summary. It keeps RSS original preview, extraction time, extraction method, visible extracted-character count, and changed final URL in the summary area, with `ContentExtractionPill` as the right-side status; it does not expose raw debug JSON.
- Reader/AI detail body rendering uses the current effective `content_text` when present and falls back to preserved `feed_content_text` when page-extracted content is absent. This is important for RSSHub/Telegram/X/short-form items where the feed `description` already contains the readable post text, quoted content, and images.
- The capture summary card is conditional. It appears for page-extraction-related states: extracted page / succeeded, or `failed` / `needs_extraction` after an extraction attempt. It does not appear for plain `contentTextSource === "feed_content"` items where RSS/Atom already provides the usable body and no page extraction is needed.
- `ContentExtractionPill` reports authoritative backend extraction status before frontend heuristics: `failed` takes precedence over older extracted content, and `not_needed` displays the RSS source rather than "suspected source-link-only" even when source text contains an original-link notice.
- RSS original preview comes from frontend `FeedItem.feedContentText`, mapped from Reader detail API `feed_content_text`, which returns existing database field `FeedItem.feed_content_text`. Do not use `summary` or current effective `content` as a fake RSS original preview.
- When an item has not been extracted and all available feed body candidates look short/source-link-only, `detail-pane.tsx` exposes a “报告并提取正文” action that starts `POST /api/operations/feed-items/{feed_item_id}/extract-content` for that one item through `operation-service.ts`.
- `feed-service.ts`, `homepage-service.ts`, `knowledge-service.ts`, and `types/feed.ts` carry DTO/view-model fields for `content_text_source`, extraction status/timestamps/error, and read-only derived diagnostics: extraction method, final URL, and visible-character count.
- `use-info-flow-app.ts` merges extraction responses into reader/homepage projections and refreshes AI/homepage data when extraction changes the effective `content_text`.
- Backend ownership stays split: `source_sync.py` saves original feed content and triggers automatic item-level extraction checks; `operations.py` / `operation_jobs.py` own manual report-and-rerun; `insight_engine_artifacts.py` owns artifact rebuild/input choice after extraction.
- The default backend extractor path is lightweight: `httpx + readability-lxml` reader HTML plus quality gates, with `trafilatura` retained as fallback. HTML fetch may follow up to two in-page `meta refresh` redirects before extraction; `<link rel="canonical">` is not followed as a redirect. Redirect detection scans up to the current 500 KB page prefix, and debug payloads record followed redirects as `html_redirects`. If the latest failure is `quality_failed: extracted text is too short`, the backend may make one lightweight retry by refetching, resolving redirects again, and rerunning readability-lxml then trafilatura. Automatic extraction treats non-URL, non-jump visible feed/RSSHub text from `t.me`, `telegram.me`, `x.com`, `twitter.com`, and `okjike.com` as complete short-form body content with reason `short_form_feed_content`; manual force extraction still runs the fetch/extractor path. `readability-lxml` output is stored as reader HTML after normalizing article links/images to absolute `http/https` URLs and removing `img srcset`; frontend sanitization remains the display safety boundary. Do not call `capture_tools/crawl4ai_wrapper.py` or browser fallback from default feed sync; Crawl4AI remains capture/archive tooling.
- While manual extraction is pending, the frontend clears stale derived extraction diagnostics in the selected detail state so an older method/final URL/character count is not displayed as the current run.
- Manual re-extraction quality gates use the preserved feed baseline (`feed_content_text`, then `summary_text`) rather than previous extracted page content.
- `insight_engine_artifacts.py` re-cleans homepage summary artifacts on read and rebuild, and resolves homepage routing artifacts plus deterministic fallback. URL-only jump prompts such as "read more" plus a URL should become absent summaries and should not contribute the ranking `has_summary` reason.

- The app favicon and top-bar brand mark share `frontend/public/infoflow-icon.svg`. Keep the browser favicon links in `frontend/index.html` and the top-bar image in `top-bar.tsx` pointed at the same tracked asset unless a later branding change intentionally splits them.
- Source management category grouping is a display grouping over `SourceDto.folder_path`; `未分类` is used only when a source has no folder path and does not change the persisted source record.
- Source category management belongs to subscription sources only. It must not edit Insight Engine taxonomy/content types/reason codes. Rename and delete actions operate on exact full `folder_path` values, not inferred parent/child trees; delete clears matching source `folder_path` values and does not delete source rows.
- `SourcesWorkspace` must use preview `canonical_url` when creating an RSSHub source. `resolved_url` is fetch diagnostics only and changes when `rsshub_base_url` changes.
- OPML preview UI should expose candidate `status`, `kind`, `input_url`, canonical `url`, `folder_path`, duplicate/matched/invalid messages, selection state, per-candidate editable category, and per-candidate `ai_route` so skipped or invalid entries remain inspectable.
- OPML commit UI should let the user apply a bulk AI route to selected candidates and override each selected candidate's route and category individually. The frontend should submit only selected `candidate_id` values plus selected routes/categories to `/api/sources/imports/opml/commit`.
- Import mode keeps the OPML upload and candidate list in the center pane. The right preview pane is resizable on desktop and can display single-source preview results or an OPML candidate's fetched metadata and recent entries after the user clicks that candidate's content preview action.
- The Local Mirror panel displays backend-provided paths and file counts as diagnostics; it must not read from `KnowledgeBase/` directly.
- Knowledge detail layout order is title/source/note/status chips, saved item insight, capture processing, archive artifacts, Local Mirror, then the primary reading body.
- Knowledge detail archive actions use backend `archive_artifacts` metadata. SingleFile HTML and page images open asset content URLs; raw/fit/image-reinserted markdown can be previewed inline or opened/downloaded through snapshot content URLs.
- Archive artifact availability reflects PostgreSQL snapshots/assets. Local mirror status is displayed as a separate derived export status and must not gate database artifact preview/download actions.
- Knowledge detail local mirror path display includes KnowledgeBase root, article directory, raw, fit, image-reinserted fit, uploaded markdown, markdown assets, SingleFile, optional source material, and manifest paths supplied by the backend. It must not infer title slug filenames locally.
- Knowledge detail's primary reading body is selected on the frontend in this order: `uploaded_markdown_v1`, `crawl4ai_fit_image_reinserted_markdown_v1`, `crawl4ai_fit_markdown_v1`, `crawl4ai_raw_markdown_v1`, legacy `content_html`, then empty state. This is a display path, not a new backend contract.
- `KnowledgeMarkdownReader` uses `react-markdown`, `remark-gfm`, and `rehype-sanitize`; it must not enable raw HTML execution for database Markdown.
- `ifa-asset://<asset_key>` references are rewritten only for app rendering to the configured frontend API base plus `/api/knowledge/assets/{asset_key}/content`. The rewrite must not be persisted back into snapshots or used to change Local Mirror export semantics.
- Capture processing, archive artifacts, and Local Mirror panels persist collapsed/expanded UI state in localStorage key `ifa:knowledge-detail-collapsed-panels:v1`. This is client-only presentation state and must not be promoted to backend settings without a separate decision.
- Collapsed panel headers preserve one-line operational context: capture status/run/time/retry action; archive core availability/image count/run-or-time/open-download actions; Local Mirror export id/file count/time/status/re-export action.
- Archive artifact image assets are a second-level collapsible section, collapsed by default. The collapsed row shows available image count and expand/open-asset actions; expanded state shows image tiles plus open/download actions.
- SingleFile wrapper injects `singlefile_precapture.js` into a Playwright persistent Chromium context, loads the vendored MV3 extension from `vendor/singlefile-mv3`, applies Chinese browser locale defaults, triggers the extension through its external message bridge, observes download completion, and self-validates the saved HTML before persisting `singlefile_html_v1`. Keep wrapper options, vendor metadata, packaged extension files, Docker runtime env, and `test_singlefile_wrapper.py` in sync when changing capture timing, theme, locale, download behavior, or extension id/pin.
- Crawl4AI wrapper uses the `crawl4ai_dynamic_markdown_v1` profile: pre-capture scrolling and body-stability waiting, `wait_for_images`, full-page scanning, iframe processing, and shadow DOM flattening. Keep wrapper constants, persisted tool args, and `test_crawl4ai_wrapper.py` in sync when changing these flags.
- Image-reinserted fit markdown is assembled in `knowledge_capture.py` from raw markdown and raw HTML image candidates. Placement uses before/after context, HTML candidate priority, and CJK/Latin significant-term matching; check `test_knowledge_api.py` before simplifying this logic.
