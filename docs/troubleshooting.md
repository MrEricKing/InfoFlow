| Frontend dev server fails with `EACCES` or `EADDRINUSE` on a port | `scripts/dev.mjs`, `frontend/vite.config.ts`, `docs/configuration.md` | Root `npm run dev` first runs the targeted frontend/backend cleanup from `scripts/dev-stop.mjs`, then checks the exact configured frontend port. It does not silently fall back to another frontend port. On Windows, check `netsh interface ipv4 show excludedportrange protocol=tcp`; if the selected port is excluded, set `FRONTEND_PORT` explicitly or free the port. Root dev also sets matching backend `CORS_ORIGINS`. |
| Backend dev server fails with `EACCES` or `EADDRINUSE` on port 8000 | `scripts/dev.mjs`, `scripts/run-backend-dev.mjs`, `frontend/src/lib/api-url.ts` | Root `npm run dev` first runs the targeted frontend/backend cleanup from `scripts/dev-stop.mjs`, then checks the exact configured backend port. It does not silently fall back to another backend port. Check `Get-NetTCPConnection -LocalPort 8000` for `Bound` owners such as local proxy software. | Backend reload stops the frontend, prints `Terminate batch job`, opens a separate conda window, or leaves backend down after a Python edit | `scripts/dev.mjs`, `scripts/run-backend-dev.mjs`, `scripts/conda-command.mjs` | Root `npm run dev` delegates backend startup to `scripts/run-backend-dev.mjs`. That script runs Uvicorn without `--reload`, watches `backend/app/**/*.py` from Node, and restarts the backend process tree on changes. The backend runner logs its Python runner, directly invokes the `infoflowaggregator` conda environment Python when available, and falls back to `conda run`. This avoids Windows Uvicorn reload control events, avoids `detached` child consoles, and avoids the normal slow `conda run` path on this machine. Unexpected backend exits are restarted instead of stopping the frontend. Restart `npm run dev` after changing these scripts because running dev processes do not hot-reload their own orchestration code. |
| Frontend starts before the backend is healthy or shows API errors during local dev startup | `scripts/dev.mjs`, `scripts/run-backend-dev.mjs`, `backend/app/api/routes/health.py` | Root `npm run dev` starts the backend first, waits for `/api/health`, then launches Vite with the selected backend URL. Re-run it safely when no matching processes are active. |

## Data Inspection Hints

Most capture and mirror failures are easier to reason about through the process tables:

- `saved_item_capture_runs`: overall capture status and requested targets.
- `saved_item_capture_tool_calls`: SingleFile/Crawl4AI execution diagnostics.
- `saved_item_capture_tool_calls.tool_args_json`: Crawl4AI calls should expose the active capture profile and `browser_capture` flags when debugging missing dynamic content.
- `saved_snapshots`: markdown/canonical/manual payloads, including `capture_page_metadata_v1` title metadata.
- `saved_item_assets`: binary assets and SingleFile HTML. Repeated captures can reuse `page_image_v1` assets by `sha256` for the same saved item.
- `saved_snapshot_asset_refs`: markdown image refs. Latest raw/fit/image-reinserted markdown snapshot refs determine which `page_image_v1` assets are exposed in current detail and Local Mirror views.
- `saved_item_mirror_exports`: local mirror export status.
- `saved_item_mirror_export_files`: written file records, relative paths, byte/hash values, and verification.
- `app_settings`: DB storage path overrides; `knowledge_base_root` controls Local Mirror. `llm_wiki/` is a reserved future workspace, not a current DB setting or Settings API field. AI profile settings live under `ai_general_*` and `ai_sensitive_*` keys, including `provider`, `enabled`, `base_url`, `model`, `deepseek_thinking`, `artifact_concurrency`, and `api_key`, with supported provider values `deepseek`, `openai-compatible`, and `lm-studio`; v3 starts from a fresh baseline and runtime does not read old flat `ai_*` fallback rows; the API should expose only masked/configured key status.
- `sources.ai_route`: per-source AI profile selector. Use it with latest source occurrence rows when checking which provider should have generated a feed item artifact for the homepage read model.
- `sources.icon_url`, `sources.icon_source`, `sources.icon_updated_at`: lightweight source icon metadata. `fallback_avatar` intentionally has no external icon URL; browser-side image load failures should fall back locally and should not mutate PostgreSQL.
- `source_fetches`: source sync diagnostics. Use `GET /api/sources/fetches?limit=50` for the global Settings history and `GET /api/sources/{source_id}/fetches` for the selected-source pane. The global history joins `sources` only to add `source_name`; fetch rows remain the canonical diagnostic record.
- `insight_profiles`: immutable user-created/imported Insight Profile versions. There should be no migration-seeded default row; Settings may return a code-level default fallback with `id = null`.
- `insight_profile_events`: profile audit trail. The latest `activated` or `rolled_back` event determines the active database profile; activation and rollback event JSON should include `previous_active_profile_id`.
- `feed_item_behavior_events`: append-only behavior evidence. Check `event_type`, `source`, `created_at`, `recorded_at`, and `event_payload_json` when state paths or evidence package counts look wrong.
- `item_states.seen_at`: title/summary-level processing state. Current status priority is `not_interested > saved > read_full > seen > browsed > unread`; do not read behavior events to derive normal current status.
- `feed_item_structured_feedback`: current structured human evidence for one feed item. It should be loaded with reader/homepage projections and exported in article JSON, but never written to `insight_engine_artifacts`.
- `GET /api/settings/ai/insight-request-preview`: safest first check for the exact current Insight Engine request body because it uses the same builder as real homepage generation while staying read-only and sanitized.
- `GET /api/settings/insight-engine/coverage`: safest first check for why feed item insight artifacts are missing across a source or globally. It should classify coverage without writing artifacts or attempts; use explicit retry/build actions only after inspecting retryability.
- `GET /api/operations/active` and `GET /api/operations/active-list`: safest first checks for long-running source/homepage/capture/mirror/detail work after refresh, duplicate start, or stop-state bugs.
- `GET /api/settings/insight-profile`: safest first check for active/default profile context, profile version history, and event history without calling AI or writing artifacts.
- `POST /api/settings/insight-profile/draft/inspect`: safest first check for an offline candidate profile because it normalizes complete candidate JSON, compares it with the active/default profile, returns field diffs and candidate prompt context, and stays read-only.
- `POST /api/settings/insight-profile/candidate/inspect`: safest first check for external Codex `profile_candidate` JSON because it validates hostile input, returns dry-run data, and separates global profile suggestions, Source Profile draft suggestions, and channel prompt/boundary suggestions without writing.
- `GET /api/settings/insight-evidence-package/preview`: safest first check for export scope, unread exclusion, artifact mode coverage, failed/skipped attempts, saved item display content, and feedback counts before downloading the ZIP.
- Homepage card `priority_source` and evidence-package article `current_insight.priority.source`: should be `backend_scoring_v1` for current Backend Scoring v1 output. Raw AI scoring evidence remains under latest raw feed item artifacts.
- `feed_items.insight_feedback_text`: user-authored item-level free-form insight feedback. It is not an Insight Engine artifact and should be trimmed/cleared only through the reader insight feedback endpoint.
- `feed_items.content_extraction_debug_json`: latest extraction diagnostics. Check `fetch.url`, `html_redirects`, `extractor.name`, `output_format`, `extracted_visible_char_count`, retry markers, and quality-gate details before changing extractor rules.
- `item_states.not_interested_at`: current state flag for the reversible `not_interested` negative scoring contribution and low-priority bucket reason. If it is null after undo, prior `not_interested` behavior events should not keep applying negative source/category history.
- `saved_items.origin_type`: saved signal source, currently `feed_saved`, `manual_url`, `markdown_upload`, `html_upload`, or `singlefile_html_upload`.
- `saved_items.ai_route`: saved item insight privacy route. Feed saves snapshot source route at save time; manual captures default to `sensitive`; rebuild follows this route unless overridden for one request.
- `saved_items.canonical_url`: nullable for upload-origin saved items. Do not invent fake URLs for local files.
- `saved_items.original_filename`, `saved_items.mime_type`, `saved_items.source_asset_id`, `saved_items.processing_status`, `saved_items.processing_error`: upload metadata and processing status for Markdown/HTML/SingleFile HTML saved items.
- `saved_item_assets.asset_kind = uploaded_source_material_v1`: original uploaded source file bytes.
- `saved_snapshots.snapshot_kind = uploaded_markdown_v1`: derived Markdown body for uploaded material reading, insight input, and Local Mirror export.
- `insight_engine_artifacts.saved_item_id`: saved item Insight Engine artifact link for `saved_item_insight_v1`; curated saved item edits do not belong here.
- `insight_engine_artifacts.feed_item_id` / `saved_item_id`: artifact rows must have exactly one owner. `saved_item_insight_v1` belongs to `saved_item_id`; `feed_item_*_v1` artifact kinds belong to `feed_item_id`. The v3 fresh baseline enforces current owner/index shape; if an old development database reports invalid artifact ids during manual inspection, fix or reimport instead of silently repairing rows.
- `saved_item_curated_insights` and `saved_item_curated_insight_events`: current curated saved item insight revision and append-only edit history.
- `saved_items.removed_at`: cancel-save soft removal. Active knowledge queries should filter it out; restore flows should clear it instead of creating duplicates.

Do not debug local mirror correctness by editing files under `KnowledgeBase/` or legacy `llm_wiki/`. Rebuild from PostgreSQL instead.
